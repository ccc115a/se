# 3.1 為什麼要用分支（Branch）？

## 沒有分支的痛苦

想像你在開發一個新功能，寫到一半，客戶回報主站有嚴重 bug 要立刻修。但你的程式碼半成品和穩定版本混在一起——你不可能直接把半成品上線，也沒辦法乾淨地只修 bug。

## 分支就是平行時空

**分支（branch）** 讓你從某個版本分出一條獨立的開發線，互不干擾：

```
main:    A ── B ── C ────────── F（修 bug）
                    \        /
feature:             D ── E（新功能開發中）
```

- `main`：永遠保持可上線的穩定狀態
- `feature`：在分支上盡情實驗，寫壞了整條丟掉也不影響 main

核心原則：**main 主線保持穩定，任何新工作都開分支做**。

這包括：

- 開發新功能（`feature/login`）
- 修 bug（`fix/safari-form`）
- 實驗新想法（`experiment/refactor`）

工作完成後，再把分支合併（merge）回 main——這是下一節的主題。

> Git 的分支非常輕量，建立分支只是記錄一個指標（幾個 bytes），不像複製整個專案。所以放心地多開分支吧。
