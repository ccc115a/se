# 2.1 記錄程式碼的變更

## 查看檔案狀態：git status

`git status` 是你最常打的指令——不知道現在什麼狀況，就先打它。

```bash
git status
```

輸出會告訴你：

- 目前在哪個分支（`On branch main`）
- 哪些檔案被修改但還沒 add（`Changes not staged`，紅色）
- 哪些檔案已 add 等著 commit（`Changes to be committed`，綠色）
- 哪些是全新的未追蹤檔案（`Untracked files`）

## 將檔案加入暫存區：git add

```bash
git add app.py        # 加入單一檔案
git add .             # 加入目前目錄下所有變更（最常用）
```

> `git add .` 是日常開發的主力，但要注意：它會把所有變更都加進來，包括不該提交的檔案（如機密設定）。所以搭配 `.gitignore` 使用（見 2.3 節）。

## 提交版本歷史：git commit

```bash
git commit -m "新增使用者登入功能"
```

`-m` 後面是提交訊息。好的訊息要說明「做了什麼」：

```bash
# 不好
git commit -m "update"
git commit -m "fix bug"

# 好
git commit -m "修正登入頁在 Safari 無法送出表單的問題"
```

**日常開發的基本節奏**就是這三步：

```bash
git status    # 看看改了什麼
git add .     # 加入暫存區
git commit -m "說明"   # 提交
```

建議每完成一個小功能或小修正就 commit 一次，commit 越小，日後回溯與撤銷越精準。

> 小技巧：`git commit` 不加 `-m` 會開啟編輯器讓你寫多行訊息；第一行寫標題，空一行後寫細節。
