# AGENTS.md

Small, non-git collection of standalone Ollama agent experiments. Each version is a from-scratch evolution of the previous one. Not a package; no build/lint tooling beyond per-version pytest suites.

## Versions (progression 1→2→3→4→5→6)
- `agent1prompt/agent1prompt.py` — v1 baseline: Ollama native function calling (`tool_calls`), one `run_shell` tool. Has pytest suite + `test.sh`.
- `agent2context/agent2context.py` — v2 = v1 + context engineering: a `ContextBuilder` class centralizing dynamic system prompt (role frame + runtime facts + tool policy + output contract), tool schemas-as-context, and token-budgeted history management with old-message summarization (instead of agent1's `trim_history` that just drops). Adds `/ctx` command to dump the assembled context. Has pytest suite + `test.sh`.
- `agent3harness/agent3harness.py` — v3 = v1 + harness engineering: an `ExecutionHarness` class that is the sole subprocess entrypoint — structured results (`ExecResult`: stdout/stderr split, exit code, duration), output truncation (`MAX_OUTPUT_CHARS`), timeout, forbidden-command guard (regex patterns for `tail -f`, servers, `watch`), strict `cwd=WORKSPACE`, and env-var allowlist isolation. Adds `/harness` command. Has pytest suite + `test.sh`.
- `agent4loop/agent4loop.py` — v4 = v1 + loop engineering: a `SelfCorrectingLoop` class that owns the agent loop — a plan→execute→reflect cycle. `run_shell` returns structured `ToolOutcome` (text + exit_code + ok) so failures are detectable; on failure the loop injects a reflection prompt (with failure details) back into the model and lets it retry with a corrected command, capped by `MAX_REPLANS` (and `MAX_TOOL_TURNS`), recording everything in a turn transcript. Adds `/loop` command. Has pytest suite + `test.sh`.
- `agent4loop2/agent4loop2.py` — v5 = 多角色分工版: a `RoleLoop` class replacing the single self-correcting agent with **three roles** — Planner (no tools, emits a plan into `plan_text`), Executor (owns `run_shell`, may take several tool rounds gated by a hard `MAX_TOOL_TURNS` budget with per-batch truncation and a running `exec_history` transcript), and Evaluator (owns the `task_done` tool; calling it ends the cycle, otherwise its feedback is handed back to the Planner for revision). Loops up to `MAX_PLAN_CYCLES`; records a per-role `TurnRecord` transcript; adds `/roles` command. `call_ollama` gained a `think` param (thinking only on Planner — Executor/Evaluator run tight so the 2b model doesn't derail). Has pytest suite + `test.sh`.
- `agent5claw/agent5claw.py` — v6 = OpenClaw 概念縮小版: a 萬用 personal assistant layering **three OpenClaw concepts** on v1's streaming loop — (1) `ClawMemory`, persistent Markdown memory (事實/偏好/專案 sections) that auto-loads at boot, injects into the system prompt each turn, and is written via a `remember` tool `/remember`; (2) `SecurityPolicy`, a run_shell approval gate (`auto`/`ask`/`deny`, injectable `prompt_fn` for tests) plus a hardcoded `DENY_PATTERNS` blocklist that refuses even in auto mode; (3) a `Skill` registry (read_file/search/sysinfo/list_files) exposed as a `run_skill` tool and the `/skills`/`/skill` commands. `handle_turn` keeps the same injectable `call_ollama_fn` hook (tests use a `FakeModel`); memory path overridable via `CLAW_MEMORY_FILE`. Adds `/memory` `/remember` `/approval` `/skills` `/skill`. Has pytest suite + `test.sh`.

- The v1 / v2 / v3 / v4 progression each adds one engineering focus: v2 = context, v3 = harness, v4 = loop. v2 keeps the same streaming loop, `call_ollama`/agent mechanics, and `run_shell`; `call_ollama` now takes `tools` as a param. v3 keeps `trim_history` and static system prompt from v1. v4 keeps `trim_history`, static system prompt, and v1's streaming; `run_shell` now returns `ToolOutcome`, and `SelfCorrectingLoop.run()` accepts injectable `tool_impls`/`call_ollama_fn` for deterministic tests. agent4loop2 (v5) swaps single-agent reflection for role separation: `RoleLoop.run()` keeps the same injectable `tool_impls`/`call_ollama_fn` hooks (tests use a `FakeRoles` fake that dispatches by role, identified via the tool-set argument). agent5claw (v6) wraps the v1 streaming loop in OpenClaw's three building blocks: `ClawMemory` supplies a persistent runtime context the model can read each turn and write via tools, `SecurityPolicy` gates every `run_shell`, and `Skill` turns common tasks into callable tools — all still driven by the same injectable `call_ollama_fn` test hook.

## Runtime requirements (easy to miss)
- Requires **Ollama running locally** at `http://localhost:11434`. All live smoke tests (`test.sh`/pytest) need the model; the deterministic unit tests do not.
- Requires `aiohttp`: `python -m pip install aiohttp` (repo has no requirements file or venv committed).
- Each script is a standalone entrypoint; there is no shared module. Run from the desired work directory with `python agent2context.py` — `WORKSPACE` = CWD at launch.

- `agent3harness/test_agent3harness.py` — 22 unit tests covering `ExecResult` formatting, safety-guard regexes, timeout/truncation/cwd/env isolation. All deterministic (no Ollama) except the `@pytest.mark.skipif` live smoke test.

- `agent4loop/test_agent4loop.py` — 13 tests using an injectable `FakeModel` (scripted tool/content responses) to cover success paths (no reflection), fail→reflect→retry, `MAX_REPLANS`/`MAX_TOOL_TURNS` budget caps, parallel tool calls in one turn, and turn-transcript rendering. No Ollama except the `@pytest.mark.skipif` live smoke test.
- `agent4loop/test.sh` — scenario test: echo probe runs, `nosuchcommand` fails and triggers reflection/retry, `/loop` renders, clean `/quit`.
- `agent4loop2/test_agent4loop2.py` — 9 tests using an injectable `FakeRoles` fake (per-role scripted tool/content responses) to cover single-cycle success (`task_done`), evaluator-feedback → planner-revision, `MAX_PLAN_CYCLES` cap, `MAX_TOOL_TURNS` per-batch truncation, parallel tool calls, and `/roles` rendering. Needs Ollama + model.

## Config & behavior knobs (top of each .py)
- `WORKSPACE` (CWD), `MAX_TOOL_TURNS` (5), `HISTORY_MESSAGES` (12), `SHELL_TIMEOUT` (30s). v2 adds `TOKEN_BUDGET`. v3 adds `MAX_OUTPUT_CHARS`. v4 adds `MAX_REPLANS`. v5 adds `MAX_PLAN_CYCLES`.
- Add new tools by appending to `TOOLS` (Ollama function schema) and registering in `TOOL_IMPLS`; in v3 route execution through `HARNESS.execute()` so safety/truncation/timeout apply uniformly; in v4 the loop reads `ToolOutcome.ok` to detect failures and trigger reflection; in v5 executor tools live in `EXEC_TOOLS` and the Evaluator's `task_done` in `EVAL_TOOLS`, both dispatched through `RoleLoop`; in v6 `handle_turn` builds `TOOL_IMPLS` via `build_tool_impls(memory)` so `remember`/`run_skill` can close over the shared `ClawMemory`.
- The `run_shell` tool runs `shell=True` in `WORKSPACE`; the system prompt, v3's `ExecutionHarness`, and v6's `SecurityPolicy.DENY_PATTERNS` all forbid non-terminating commands (`tail -f`, servers).

## CLI
- `/quit` `/exit` `/q` to quit, `/clear` to reset history. v2: `/ctx`. v3: `/harness` to view harness config. v4: `/loop` to view loop state. v5: `/roles` to view the three-role dispatch transcript. v6: `/memory` `/remember` `/approval` `/skills` `/skill`.
