## Prerequisites

This exercise is macOS only. Building a native Mac app needs a Mac and Apple's developer tools.

There are two separate things people often confuse:

- **Command Line Tools** give you `git`, `clang`, and the Swift compiler. OpenCode will install them for you from your session with `xcode-select --install`.
- **Full Xcode** is the large app from the Mac App Store that includes `xcodebuild` and the macOS SDK. You need it to build an actual `.app`. Command Line Tools alone are not enough for this project.

OpenCode Stats targets **macOS 15.6+** and builds with **Xcode 26 or newer** (stable, no beta needed). The agent will check what you have with `xcodebuild -version` and walk you through installing Xcode if it's missing.

## The skill

You'll install [`macos-app-skills`](https://github.com/fayazara/macos-app-skills), a collection of agent skills for building native macOS apps in SwiftUI and AppKit:

```
npx skills add fayazara/macos-app-skills -g -y
```

The `-g` flag installs the skill globally (for all your projects) and `-y` skips the interactive prompts, so it installs in one shot. It bundles skills for building from the command line (`build`), native macOS patterns for web developers (`macos-patterns`), settings windows, Sparkle auto-updates, notch overlays, and release pipelines. These encode the hard-won patterns that AI agents usually get wrong, so OpenCode builds and edits the app correctly instead of guessing.

Skills load at startup, so **quit and reopen OpenCode Desktop** after installing.

## How the build works

A native Mac app isn't a web project: there's no dev server and no `npm run dev`. "Running it" means compiling an actual `.app` and launching it. OpenCode Stats is an Xcode project, so the agent uses the [`build` skill](https://github.com/fayazara/macos-app-skills) to compile it with `xcodebuild` from your session, then opens the result.

A few things are worth knowing before you start, so the output makes sense:

- **`xcodebuild`** is Xcode's command-line build tool. The agent points it at the `OpenCode Stats.xcodeproj` and the "OpenCode Stats" scheme. The first build is slower than later ones, since Xcode has to resolve the project's dependencies before it can compile.
- **Code signing** is macOS's way of stamping an app with a developer identity. The project ships with the author's signing settings, which won't match your machine, so the agent either swaps in your own or turns signing off for a local build. The `build` skill knows how to handle this, so a build failure here is expected and recoverable, not a dead end.
- **It's a menu bar app.** There's no window when it launches. You'll find its icon in the menu bar at the top of the screen and click it to open the popover.

The app reads your real usage from the local OpenCode database (`~/.local/share/opencode/opencode.db`), so the numbers you see are your own. If you've never run OpenCode on this machine, the stats will be empty until you do.

## What you'll do

- Set up Apple's developer tools by installing Xcode and the Command Line Tools, with the agent checking what you already have.
- Install the `macos-app-skills` skill, then restart OpenCode Desktop so it loads.
- Clone the OpenCode Stats repository from GitHub onto your machine.
- Build the app from source with `xcodebuild`.
- Run the app and find its icon in your menu bar.
- Make a small change, like tweaking the menu bar label or the popover, then rebuild to see it.
- Optionally open a pull request to share your change with the upstream repo.

## Share your work

Once your change is working, you can offer it back to the project. The agent will help you fork the repo, push your change to a branch, and open a pull request against [`fayazara/opencode-stats`](https://github.com/fayazara/opencode-stats) using the `gh` CLI from the [Use Git and GitHub](/exercises/use-git-and-github) exercise. Whether or not the maintainer merges it, a thoughtful PR is a real open-source contribution. This step is optional, skip it if you'd rather keep your change local.

## Build your own

Building someone else's app teaches you the flow: set up the tools, build, run, change, repeat. Once that clicks, you can point OpenCode at a brand-new app of your own. It doesn't have to be a menu bar app, it can be any kind of macOS app: a regular windowed app, a document-based app, a settings-driven utility, whatever you want to make. Describe the app you have in mind and let OpenCode scaffold it from scratch.

You can also explore the rest of [Fayaz's open-source projects](https://github.com/fayazara/fayazara), like [Kaze](https://github.com/fayazara/Kaze) (local speech-to-text) or [Screendrop](https://github.com/fayazara/Screendrop) (screenshots and recording), and build any of them the same way.
